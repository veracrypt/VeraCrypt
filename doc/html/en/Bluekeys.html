Documentation Encrypted Keyfiles

Encrypted Keyfiles (Bluekeys)

An encrypted keyfile combines an external file with an RSA private key on a security token. VeraCrypt encrypts the secret prefix of a generated random keyfile with the token's public key. When opening a volume, the token decrypts that prefix; the resulting keyfile is combined with any volume password in the usual way. The private key is not exported.

Requirements and compatibility

This feature is available in the Linux, macOS and other Unix builds. It is not implemented in the native Windows application and cannot be used for pre-boot authentication. It does not change the volume format. Ordinary keyfiles and token-stored data keyfiles continue to work as before when no encryption key is selected.

Configure a compatible PKCS #11 library under Settings > Security Tokens, or supply --token-lib in text mode. Provision an RSA key pair using the token vendor's tools. The public key must permit encryption and the private key must permit decryption. VeraCrypt supports RSA keys from 2048 to 16384 bits, subject to the token's limits, and requires RSA OAEP with SHA-256 and MGF1-SHA-256. There is no fallback to SHA-1, PKCS #1 v1.5 padding, or raw RSA. ECC and signing-only keys are not supported.

The PKCS #11 library must expose the matching public/private objects and the OAEP mechanism. A mechanism listing alone does not guarantee support for its SHA-256 parameters; verify a complete create/open/export cycle with the particular card, firmware and library before relying on it. The Yubico YKCS11 documentation describes its PIV PKCS #11 interface. Support is library-dependent; not every PIV library exposes the same operations.

Creating and using an encrypted keyfile

  1. Open Tools > Keyfile Generator, select a security token encryption key, and generate a keyfile. The size setting describes the decrypted keyfile; encryption adds 66 bytes.
  2. When creating or opening a volume, enable keyfiles, add the encrypted file, and select its matching security token decryption key. Enter the token PIN when requested.
  3. Use the same file and private key for subsequent mounts, password changes and header backup/restore. A hidden volume has a separate token-key selection in its protection options.

A token-key selection applies to every external file in that keyfile list, including files in an added directory. Do not mix ordinary and encrypted files, or files encrypted for different keys, in the same list. Token-stored data keyfiles and EMV keyfiles cannot be combined with a selected encryption key. The encrypted format has no marker and is not detected automatically: always select the decryption key when using it.

For unattended text-mode use, first list available descriptors:

veracrypt --text --token-lib=/path/to/library.so --list-security-token-keys

The list distinguishes encrypt and decrypt descriptors. Copy the complete descriptor, including spaces, and quote it. For example:

veracrypt --text --token-lib=/path/to/library.so --create-keyfile /path/to/bluekey --security-token-key='ENCRYPT_DESCRIPTOR'
veracrypt --text --token-lib=/path/to/library.so --keyfiles=/path/to/bluekey --security-token-key='DECRYPT_DESCRIPTOR' /path/to/volume

The same --security-token-key option applies to --create and to the current keyfiles with --change. Use --new-security-token-key with --new-keyfiles for the new credentials, and --protection-security-token-key for hidden-volume protection. An empty descriptor selects ordinary keyfile processing.

Descriptors generated by VeraCrypt use the token serial number and binary key ID when available, so public and private key labels may differ and reader slot changes are tolerated. Tokens without a serial number use a slot-based descriptor. The original slot:label:RSA PKCS#1 OAEP syntax remains supported when the label is unique. Ambiguous key or token selections are rejected. Keep a record of the correct descriptor; it is not stored inside the encrypted keyfile or volume.

Recovery and security considerations

Before using a token to protect important data, prepare and test a recovery method. Losing the token, its private key, the PIN or the encrypted keyfile can make the volume inaccessible. A copy of the encrypted keyfile alone cannot replace the token.

Tools > Export Decrypted Keyfile creates a recovery keyfile after confirmation and token authentication. Use this file as an ordinary keyfile with the security token key field empty. It provides access without the token (and still requires the volume password, if set), so keep it separately in secure storage. Newly written encrypted and decrypted keyfiles have owner-only permissions. Export does not overwrite the input file, including aliases to it.

Only the initial RSA plaintext block is encrypted; the remaining random bytes are stored in cleartext. The format is an encrypted random keyfile prefix, not a general-purpose authenticated file-encryption format. Changes to either part change the volume credentials. VeraCrypt processes at most the first 1 MiB of the reconstructed keyfile, as with ordinary keyfiles.

Do not enable password caching when a fresh token operation must be required for every mount. Cached derived credentials can open a volume without repeating the token operation. Close token sessions when finished; token PIN caching and per-operation PIN or touch requirements depend on the token and library. This feature does not protect decrypted key material from a compromised host while VeraCrypt is using it.
